> **Rationale:** Single SPA for all four roles (stories 1-15) calling events-api (build-order edge); gated on user-auth thunder-app provisioning.

## Scope
Implement the React SPA per specs/design/components/conference-webapp/design.json, honouring its prototype (prototype.json, prototype.tsx) screen for screen. Calls only events-api (openapi.yaml); sign-in via Thunder SSO (user-auth thunder-app platform gate); role-based navigation per security.json. Oxygen UI design system.

Screens: Events (screen.events), Event detail (screen.event-detail), Session detail (screen.session-detail), My proposals (screen.proposals), Review queue (screen.review-queue), Proposal decisions (screen.decisions), My registrations (screen.my-registrations), Account (screen.account), Settings (screen.settings), Signed out (screen.signed-out)

Flows:

- [ ] **Flow 1 · Create an event with rooms and sessions** (`flow.create-event`)
  Persona: Organizer
  Stories: 1, 2, 3
  Walk: Events → Event detail
- [ ] **Flow 2 · Decide on scored proposals** (`flow.decide-proposals`)
  Persona: Organizer
  Stories: 7, 8
  Walk: Proposal decisions
- [ ] **Flow 3 · Watch registrations and waitlist per session** (`flow.session-oversight`)
  Persona: Organizer
  Stories: 15
  Walk: Session detail
- [ ] **Flow 4 · Submit a talk proposal and track it** (`flow.submit-proposal`)
  Persona: Speaker
  Stories: 4, 5
  Walk: My proposals
- [ ] **Flow 5 · Score a proposal** (`flow.score-proposal`)
  Persona: Reviewer
  Stories: 6
  Walk: Review queue
- [ ] **Flow 6 · Browse events and register for a session** (`flow.browse-and-register`)
  Persona: Attendee
  Stories: 9, 10, 11, 12
  Walk: Events → Event detail → Session detail
- [ ] **Flow 7 · Review and cancel my registrations** (`flow.manage-registrations`)
  Persona: Attendee
  Stories: 13, 14
  Walk: My registrations

No flow: none — every story is walked above (sign-in/out is owned by platform SSO; waitlist promotion, story 13, shows as a registration's status).
