Version `v1`: the spec is `specs/` at tag `v1`.

- [ ] **foundation** Shared setup and product-wide requirements: `inventory-service`, `procurement-api`, `procurement-webapp`. Set up all three components first. The web app calls only the procurement API (P2), and the API alone calls the inventory service (P1). Wire Thunder SSO in the web app and the API, with the gateway assertion and scope gates from security.json (P4). Stock is the sum of ledger entries (P3). Keep pages fast (P5).
- [ ] **F1** Catalogue: `inventory-service`, `procurement-api`, `procurement-webapp`. Build the item CRUD in the inventory service. The API fronts it with items:read and items:manage. The web app builds the Catalogue screen; the item detail screen is for clerks. The SKU is immutable and a duplicate SKU returns 409.
- [ ] **F5** Stock and ledger: `inventory-service`, `procurement-api`, `procurement-webapp`. Build the ledger and stock reads. The inventory service exposes the append-only ledger, and the API exposes /items/{id}/ledger and /ledger (clerks only). The web app builds the item ledger section and the Stock ledger screen. Requesters see stock only, never the ledger.
- [ ] **F2** Purchase requests: `procurement-api`, `procurement-webapp`. Build the /me/requests endpoints, with own-rows access from the caller's identity. Copy the catalogue prices when the request is submitted. Editing a pending request returns it to draft. The web app builds the My requests, New request and Request detail screens.
- [ ] **F3** Approvals: `procurement-api`, `procurement-webapp`. Read the approval limit from the APPROVAL_LIMIT_DEFAULT and APPROVAL_LIMITS config. Hide requests above the limit. Refuse self-decisions, a rejection without a reason, and a second decision on a decided request. The web app builds the Approvals, Approval detail and Decisions screens.
- [ ] **F4** Goods receiving: `inventory-service`, `procurement-api`, `procurement-webapp`. POST receipts in the API. Refuse over-receipt and any request that is not approved. Then append one ledger entry per line through the inventory service, which raises stock. Set the request to received when every line is complete. The web app builds the Goods to receive and Receive goods screens.
- [ ] **F6** Low-stock view: `inventory-service`, `procurement-api`, `procurement-webapp`. Build /low-stock, listing active items strictly below their reorder level with the shortfall, sortable by shortfall or name. It is visible to requesters and clerks, not approvers. The web app builds the Low stock screen with 'Request this item', which opens New request with the item preselected.

Product-wide: P1, P2, P3, P4, P5
