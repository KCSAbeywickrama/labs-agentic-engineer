Version `v1`: the spec is `specs/` at tag `v1`.

- [ ] **foundation** Shared setup and product-wide requirements: `helpdesk-api`, `helpdesk-webapp`. Scaffold both components for the first time. Wire Thunder sign-in (user-auth) in the web app and token validation plus scope gating from security.json in the API. Implement the P1 status set, the P2 SLA computation, the member records and the shared app shell with role-based navigation.
- [ ] **F1** Raise and track tickets: `helpdesk-api`, `helpdesk-webapp`. Build the /me and /me/tickets endpoints first, then the My tickets, Raise a ticket and My ticket screens against them. Editing is allowed only while the ticket is open, and a priority change recomputes slaDueAt.
- [ ] **F2** Ticket handling: `helpdesk-api`, `helpdesk-webapp`. API first: triage, claim, assign, start, resolve and reopen, with the status transitions enforced (409 otherwise). Assign accepts an id or a typed username, and an unseen username binds on that person's first call. Add GET /agents and the web app's Ticket screen actions. Reopening keeps the original SLA due time.
- [ ] **F3** Ticket comments: `helpdesk-api`, `helpdesk-webapp`. Build both comment endpoint sets, /me/tickets/{id}/comments and /tickets/{id}/comments, listing oldest first. Add the comments section to the My ticket and Ticket screens. Comments are allowed in any ticket status.
- [ ] **F4** Queue and SLA monitoring: `helpdesk-api`, `helpdesk-webapp`. Build GET /tickets with the status, priority, assigneeId (including 'unassigned'), slaBreached and pagination filters, ordered by soonest SLA due time. A ticket with a pending typed username is not 'unassigned'. Build the web app Queue screen with its combinable filters and SLA breach marking.

Product-wide: P1, P2, P3
