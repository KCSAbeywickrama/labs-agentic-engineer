> **Rationale:** Delivers the staff-facing SPA screens for the dashboard, onboarding records, department task queues, and template management.

## Scope

Implement the onboarding-webapp SPA per `specs/design/components/onboarding-webapp/design.json`, driving all data from onboarding-api, using the screens of its prototype (`prototype.json`, `prototype.tsx`).

Screens: Dashboard (screen.dashboard), New onboarding (screen.new-onboarding), Onboarding detail (screen.onboarding-detail), IT task queue (screen.it-queue), Facilities task queue (screen.facilities-queue), Task templates (screen.templates), Account (screen.account), Settings (screen.settings), Signed out (screen.signed-out)

Flows:

- [ ] **Flow 1 · Start a new hire's onboarding** (`flow.create-onboarding`)
  Persona: HR Coordinator
  Stories: F1.1, F1.2
  Walk: Dashboard → New onboarding → Onboarding detail
- [ ] **Flow 2 · Add, edit or remove a task** (`flow.manage-exceptions`)
  Persona: HR Coordinator
  Stories: F1.3, F1.4
  Walk: Onboarding detail
- [ ] **Flow 3 · Monitor onboarding progress across departments** (`flow.monitor-dashboard`)
  Persona: HR Coordinator
  Stories: F3.1, F3.2
  Walk: Dashboard
- [ ] **Flow 4 · Mark onboarding complete** (`flow.complete-onboarding`)
  Persona: HR Coordinator
  Stories: F1.5
  Walk: Onboarding detail
- [ ] **Flow 5 · Work the IT task queue** (`flow.it-tasks`)
  Persona: IT Staff
  Stories: F2.1, F2.2, F3.2
  Walk: IT task queue
- [ ] **Flow 6 · Work the Facilities task queue** (`flow.facilities-tasks`)
  Persona: Facilities Staff
  Stories: F2.3, F2.4, F3.2
  Walk: Facilities task queue
- [ ] **Flow 7 · Maintain standard task templates** (`flow.manage-templates`)
  Persona: Admin
  Stories: F4.1
  Walk: Task templates

No flow: none — every story is walked above (story F3.2, overdue flagging, shows on the dashboard and both task queues).

All data reads/writes go through onboarding-api's REST endpoints; sign-in via Thunder SSO (platform-resource, no Task). No file/document upload UI and no notification UI (out of scope per PRD).

## Acceptance

- Every screen in `prototype.json` is built and wired per what `prototype.tsx` shows and where each control leads.
- Each flow's walk is fully navigable end to end for its role, gated per `security.json` roles/grants.
- Overdue tasks are visibly flagged (badge/indicator) on Dashboard, Onboarding detail, and each department's task queue.
- Onboarding-record completion is blocked in the UI when tasks remain incomplete (mirrors API 400).
- Mock-mode smoke walk of every flow passes per the `mock-verification` skill.
