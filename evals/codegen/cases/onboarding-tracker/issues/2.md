Version `v1`: the spec is `specs/` at tag `v1`.

- [ ] **foundation** Shared setup and product-wide requirements: `onboarding-api`, `onboarding-webapp`. Set up both components for the first time: Ballerina service with the gateway-assertion check and the Thunder user-auth wiring, and the React SPA with Oxygen UI, SSO sign-in and role-based screen gating (P1). Persistent storage is not provisioned, so use in-memory storage behind a clean boundary. Keep tasks text-only (P3) and send no notifications (P2).
- [ ] **F1** Onboarding plans: `onboarding-api`, `onboarding-webapp`. Build /onboardings, close and /onboardings/{id}/tasks endpoints; creating an onboarding seeds the default IT/HR/Facilities tasks with due dates as offsets from the start date. The web app adds the home list, start-onboarding form and detail screen with task add/edit/remove, following the prototype. The default template contents are an open question, so assume one task per department.
- [ ] **F2** Task tracking: `onboarding-api`, `onboarding-webapp`. Add the department-scoped /me/it, /me/hr and /me/facilities operations (list, complete, reopen, notes), plus /me, /tasks and /tasks/{id}/complete. Derive the department from the scopes in the assertion, and return 404 for tasks of another department. The web app adds the team home with notes and the coordinator's per-department counts and All tasks filters.
- [ ] **F3** Overdue reminders: `onboarding-api`, `onboarding-webapp`. Compute overdue, daysOverdue, dueSoon (2 days) and the onboarding overdueCount on the API, with TaskPage.overdueCount and the overdue filter on /tasks, most overdue first. The web app adds overdue highlighting and counts on the team home, the coordinator Overdue screen and the overdue flags in the onboardings list. The flags are in-app only.
