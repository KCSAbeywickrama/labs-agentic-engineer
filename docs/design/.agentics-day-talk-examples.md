## Keynote / Featured Talks

### MCP in 2026: Context is All You Need
- **Speaker:** David Soria Parra — Member of Technical Staff, Anthropic (creator & Lead Core Maintainer of MCP)
- **Time:** 13:35 CET
- **Description:**

MCP has grown from a specification into an ecosystem. In this talk, David Soria Parra—creator and Lead Core Maintainer of the Model Context Protocol—shares where MCP stands today, what the community has built, and what's on the horizon.

We'll cover:

* The growth of MCP adoption: from early adopters to production deployment
* Key protocol developments: authentication, tasks, and the extensions model
* Challenges of MCP: Context bloat, client support and OAuth
* What's next: the roadmap for MCP in 2026 and beyond
* How to get involved: contributing to the spec, SDKs, and governance

### The New AI Coding Fabric
- **Speaker:** Patrick Debois — AI Product Engineer, Tessl
- **Time:** 14:05 CET
- **Description:**

AI-driven development is outgrowing the IDE and traditional build systems. A new layer of infrastructure is forming — the AI Coding Fabric — built to support autonomous coding agents.

Exposing an MCP service is only the beginning. To truly enable AI-native software development, we'll need systems for things like:
- spec driven development versioning , spec evals and spec registries
- support for long running coding sandboxes for our Agents
- proxies that easily switch between different coding models and agents
- review at scale of parallelized agent artefacts
- coding guardrails and tracing/observability
- knowledge base systems optimized for development learnings to improve ourselves , the team and the agents

This is already taking shape through emerging tools and prototypes in the open-source and cloud-native ecosystems. You'll see how these patterns might soon extend — and challenge — the foundations we've built around IDEs, CI/CD, and service-oriented architectures.

### Beyond Vibecoding: The Coach/Player Model for Actual Autonomous Development
- **Speaker:** Douwe Osinga — Block
- **Time:** 15:20 CET
- **Description:**

We introduce and demonstrate dialectical autocoding: a novel approach to AI-assisted software development that transcends the limitations of current vibe coding tools through a structured coach-player feedback loop. With a bounded, adversarial process between two cooperating agents, we show how AI can make substantially more progress on complex coding tasks, resulting in better tested, more robust outcomes, while working around fundamental attention and human-in-the-loop limitations.

Both agents begin with the same goal: comprehensive requirements that describe the particulars of the problem. The requirements steer clear of implementation details or instructions, save certain basic guidance such as choice of programming language/target platform, allowing agents flexibility in arriving at its solution.

We believe this approach to cooperative autocoding is able to maintain goal persistence (long-horizon tasks with zero interruptions to humans that are directing the work.

### Keeping Your Agents in Check: Layered Security for Agentic Platforms in Production
- **Speakers:** Evaline Ju — Senior Software Engineer, IBM Research; Kelly Abuelsaad — AI Platform Architect & Engineer, IBM
- **Time:** 15:55 CET
- **Description:**

As AI agents move into production, safety, reliability, and security must extend beyond the models themselves to every layer of the platform. This talk explores a layered approach to securing agentic platforms, from identity and authorization to guardrails and operational checks. We discuss how risks like prompt injection, manipulated outputs, and unauthorized tool access can be mitigated using both rule-based and AI-driven approaches. We will present a reference architecture where guardrails are applied at the Envoy gateway layer and cryptographically verifiable trust is established between agents and tools through OAuth 2.0 delegation with Keycloak.

Attendees will learn the unique risks that accompany agentic applications along with practical strategies for scaling these safety mechanisms — all while maintaining performance and flexibility in production environments.

### Fantastic Vibes and Where To Find Them
- **Speakers:** Erica Hughberg — Tetrate (Envoy AI Gateway Maintainer); Mauricio Salatino — Diagrid / Dash0 (Ecosystem Engineer)
- **Time:** 16:30 CET
- **Description:**

Everyone's heard "I vibe-coded an entire architecture" or seen "AI built it beautifully but it doesn't work." This talk examines what actually works when teams use AI agents to code.

We look at four categories: which pull requests ship versus get reverted, which agent bots developers love versus uninstall, whether AI helps non-developers contribute, and patterns separating productivity wins from frustration.

Is isn't all about capability—it's also guidance. When teams use machine-readable conventions telling agents how projects work, productivity jumps. When they don't, agents fail silently. We'll review real cases of good and bad vibes, including one team safely removing 100K+ lines while another wasted days on broken code.

You'll learn concrete patterns: narrow scope wins, validation gates catch issues, human review before merge, and hybrid workflows for different task types. Practical, evidence-based guidance on when AI amplifies productivity and when guardrails are essential.

## Lightning Talks ⚡

### How I Built My Laptop Into an MCP Server To Create Secure Cloud Native Infrastructure
- **Speaker:** Mahendran Selvakumar — Tata Consultancy Services Limited
- **Time:** 14:35 CET
- **Description:**

Most teams still build new cloud native services by copying old YAML and hoping required labels, probes, limits, and security rules are correct. This is slow, hard to review, and does not scale across many clusters.

In this session I show how I turned my laptop into an MCP server that can generate a first version of secure cloud native infrastructure from a simple request. I describe a service in plain language such as name, image, ports, rollout needs, access level, and autoscaling range. The server returns structured output plus a baseline security posture. This includes probes, required labels, resource requests and limits, safe container settings, and allowed traffic.

MCP acts as the control layer. The server does not change clusters directly. It produces consistent and reviewable output that can be approved and rolled out in a predictable way, cutting review effort by about 40% and reducing drift across clusters by about 30%

### Securing AI Agents: Applying Service Mesh Patterns To MCP
- **Speaker:** Shriya Chaitanya Kamat Tarcar — AI Engineer, Nuvama Wealth Management Limited
- **Time:** 17:30 CET
- **Description:**

Although most MCP implementations lack basic authentication, AI agents are being deployed with system-level permissions, database access and API keys. Microservices security crisis is being recreated by the cloud native community but with agents capable of code modification, data exfiltration and attack propagation.

Informed by AI agent PoCs,this talk will show how service mesh security patterns translate directly to MCP deployments.To demonstrate how mutual TLS authentication, zero-trust boundaries and policy enforcement relate to inter-agent and agent-to-server communication, this talk will look at MCP protocol specification, Istio and Linkerd security models.

Attendees will receive:1)Threat model that connects MCP attack vectors with locations in service mesh.2)Authentication patterns for MCP servers. 3)Framework for deploying security patterns.Before production deployments cause supply chain incidents, session will provide the security foundation that agentic ecosystem needs.

### How AI Agents Are Ending Interrupt-Driven Platform Work
- **Speaker:** Sunny Whang — Platform Engineering Architect, Cisco
- **Time:** 17:45 CET
- **Description:**

Platform engineers face relentless interrupts - supporting dozens of service owners while drowning in repetitive tickets for upgrades, provisioning, and troubleshooting. We built a multi-agent system at Outshift by Cisco to solve this internally. After proving its impact, we open-sourced it as CAIPE: Community AI Platform Engineering (now part of CNOE) - because this pain point affects platform teams everywhere.

You'll see our production demo, architecture breakdown, and practical lessons from deploying agents in production.

## Patterns observed (for your own submission)

**Which topics actually got accepted (11 substantive talks):**
- **AI-assisted / autonomous coding — 3 talks** (The New AI Coding Fabric, Beyond Vibecoding, Fantastic Vibes). The single busiest lane.
- **Platform engineering & AIOps — 3 talks** (Adobe AIOps, Cisco/Outshift CAIPE, TCS laptop-as-MCP-server).
- **Securing agents / MCP — 2 talks** (IBM layered security, Nuvama service-mesh patterns).
- **Getting agents to production / "day 2" — 2 talks** (Solo.io, Tetrate) — both explicitly *Sponsored Keynotes*.
- **The MCP protocol itself — 1 keynote** (Anthropic).

Takeaway: every accepted talk attaches the agent/MCP idea to a *workflow, a platform, or the protocol*. There are no abstract "here's a cool agent I built" talks — each one answers "applied to what, and what changed."

**Who's on stage:** a deliberate mix of (a) end-user production stories from recognizable orgs (Block, Adobe, Outshift by Cisco, IBM), (b) the protocol maintainer (Anthropic), and (c) vendors — but the two overtly vendor talks are *labeled* "Sponsored Keynote." Unsponsored slots read as a practitioner sharing real experience, not a product pitch. Frame your ASDLC talk as a build story, not a WSO2 ad.

**Abstract anatomy (near-universal, ~120–200 words):** 1–2 sentences of concrete pain → the system/approach you built → outcomes, then a short "we'll cover / attendees will learn" list. The maintainer keynote and the Coding Fabric talk both use an explicit bulleted agenda — useful when the talk spans several subtopics.

**Evidence beats adjectives:** real numbers recur (~40% less review effort, ~30% less drift, 100K+ lines safely removed), as do named OSS projects (CAIPE/CNOE, agentgateway, kagent, agentregistry) and named tooling (Envoy, Keycloak, Istio/Linkerd, ArgoCD, Backstage, GraphRAG). Whenever a talk says "productivity improves," it immediately backs it with a specific.

**Cloud-native anchoring is expected** — it's a KubeCon co-located day. Strong abstracts hook into Kubernetes, service mesh/gateways, OAuth, or GitOps tooling. A talk with no cloud-native surface is a weaker fit for this room.

**Title conventions** — three repeating shapes:
- *Hook colon technical-subtitle*: "MCP in 2026: Context is All You Need", "Keeping Your Agents in Check: Layered Security…"
- *Provocative question*: "Is AIOps the Future of Operations?"
- *Culture-reference pun*: "Fantastic Vibes and Where To Find Them", "Rescue Agents From Prototype Purgatory", "Beyond Vibecoding".
- Lightning talks lead first-person: "How I Built My Laptop Into an MCP Server…".

**Where ASDLC fits:** you sit in the busiest lane (autonomous coding agents) but with a differentiator none of these talks have — a full *spec-driven* SDLC where webhook-driven agents open their own PRs and ship onto a Kubernetes/OpenChoreo platform. The opening pain is already validated by two accepted talks (Beyond Vibecoding, Fantastic Vibes): agents that vibe-code but can't reliably ship to production. Pitch the spec → GitHub issue → PR → build → deploy loop as the "guardrails" answer, and bring numbers (tasks merged, cycle time, revert rate). That single talk lands on coding-agents + production-readiness + cloud-native at once — the three themes the committee clearly favors.



# Sample CFP Submission 

Everyone's a Builder Now - Someone Has to Set the House Rules

Coding agents enable even non developers to build software, yet they often fail in architecture review and deployment, becoming a bottleneck in the SDLC.

This talk shares lessons from building a collaborative agentic engineering platform (https://github.com/wso2/labs-agentic-engineer) where we simulate the git lifecycle on top of the OpenChoreo platform. Every project is a GitHub repository where teams start with requirements, designs are generated per organizational practices, and tasks become issues that coding agents answer with pull requests. Reviewed and merged pull requests are built, wired, and deployed automatically.

State transitions are driven by GitHub webhooks. The agents reach the organization's resources, its APIs, databases, and configuration through the MCP. Governance of the generated artifacts rests with stakeholders such as architects and developers, who define the skills to which all architecture, code, and deployment configuration must adhere.
